# Feature Selection for Medical Data — GA vs PSO vs GWO vs WOA

Compares four metaheuristic feature-selection algorithms (Genetic Algorithm,
Particle Swarm Optimization, Grey Wolf Optimizer, Whale Optimization Algorithm)
against a full-feature baseline, on a medical classification dataset
(default: Wisconsin Breast Cancer, from `sklearn.datasets`).

Built for Kaggle Notebooks (free CPU, built-in dataset management, easy
sharing/reproducibility), but runs anywhere with the packages below installed.

## Why multiple notebooks instead of one?

Research code becomes hard to maintain as one giant notebook. Splitting by
stage keeps each notebook focused, re-runnable independently, and easy to
diff/share. All notebooks share the same `utils/` package so every algorithm
is evaluated identically — that's what makes the final comparison fair.

## Run order

1. `01_Data_Preprocessing.ipynb` — must run first; produces `datasets/*.npy`.
2. `02_Baseline_Classifier.ipynb` — produces `results/baseline_results.csv`.
3. `03`–`06` (GA, PSO, GWO, WOA) — any order; each produces
   `results/<algo>_results.csv`, `results/<algo>_convergence.npy`,
   `results/<algo>_mask.npy`.
4. `07_Comparison.ipynb` — run last; reads everything in `results/` and builds
   the final comparison table + plots.

## The one important design decision

Every notebook calls the **same** `evaluate_subset()` function
(`utils/metrics.py`) and every optimizer calls the **same** `fitness()`
function (`utils/fitness.py`). No notebook re-implements its own scoring
logic. This is what guarantees GA, PSO, GWO, and WOA are compared fairly —
same classifier, same train/test split, same metric definitions.

## Setup

```bash
pip install mealpy pymoo scikit-optimize
```

- **mealpy** — implementations of GA, PSO, GWO, WOA (and many more
  metaheuristics) used for the optimizer notebooks.
- **pymoo** — useful if you later extend this to multi-objective feature
  selection (e.g. simultaneously minimizing error rate AND feature count as
  separate objectives, via NSGA-II etc.).
- **scikit-optimize** — not essential for this phase, but a handy Bayesian
  optimization library to have available if you want to compare against
  gradient-free hyperparameter search too.

## Swapping in a different medical dataset

`utils/preprocessing.load_dataset()` supports `source="csv"` — point it at
any CSV added to your Kaggle notebook's input directory and pass the target
column name. Everything downstream (baseline, GA/PSO/GWO/WOA, comparison)
works unchanged.
